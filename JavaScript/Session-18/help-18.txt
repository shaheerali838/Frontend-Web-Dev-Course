🔸 2. Introduction to Promises
• Promises represent the eventual completion or failure of asynchronous operations.
• They provide a cleaner alternative to callback-based async code.
• Essential for handling API calls, file operations, and timed events.
• Enable better error handling and operation chaining in JavaScript.

🔸 3. Promise Creation and States
• Created using the Promise constructor with resolve and reject functions.
• Three states: pending when created, fulfilled when resolved, rejected when failed.
• .then() method handles successful promise resolution.
• .catch() method handles promise rejections and errors.
• .finally() executes code regardless of promise outcome.

🔸 4. Promise Chaining
• Multiple .then() methods can be chained for sequential async operations.
• Each .then() receives the result of the previous promise in the chain.
• Return values automatically wrap into new promises for next .then().
• Allows building complex async workflows without callback nesting.
• Provides clean syntax for dependent asynchronous operations.

🔸 5. Practical Applications
• Fetch data from APIs and handle responses using promise chains.
• Load multiple resources sequentially with dependent operations.
• Implement user authentication flows with step-by-step validation.
• Create timed animations and sequences with promise-based delays.
• Handle file uploads with progress tracking and completion handling.

🔸 6. Error Handling in Promises
• Use .catch() at the end of chains to handle any rejection in the sequence.
• Errors propagate through the chain until caught by a .catch() method.
• Multiple .catch() methods can handle different types of errors specifically.
• Always include error handling to prevent unhandled promise rejections.
• Use finally() for cleanup operations like hiding loading indicators.

🔸 7. Tips & Best Practices
• Always return promises from .then() for proper chaining.
• Handle errors at the end of promise chains with a single .catch().
• Use Promise.all() for parallel independent async operations.
• Avoid mixing promise syntax with old callback patterns.
• Keep promise chains readable by breaking complex operations into functions.
